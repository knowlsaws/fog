## 共通の受け入れ条件（全ループ）

- `Packages/Core` の `swift test` が通る（変更がある場合）
- `.github/workflows/ios-build.yml` が緑
- 要件・UI設計に反する実装をしていない。反する必要があれば `docs/04_decisions.md` に書いて PR で問う
- 秘密情報をコミットしていない
- PR 本文に受け入れ条件のチェックリストがある

## 各ループの定義

### L0 リポジトリ基盤と CI

ゴール：空のアプリが CI でビルドされ、TestFlight に上がる状態。

成果物
- `project.yml`（XcodeGen）から iOS アプリターゲット `Fog` と `FogWidgets` を生成できる
- `App/` に 5タブ（ホーム・ログ・撮影・図鑑・釣り場）のプレースホルダー。タブバーは文字なし、中央はオレンジの円
- `App/Sources/DesignSystem/` に色・フォント・余白のトークン
- `Packages/Core` が Linux で `swift test` を通す
- `.github/workflows/core-tests.yml`（Linux、Core のテスト）
- `.github/workflows/ios-build.yml`（macOS、XcodeGen → シミュレータ向けビルド）
- `.github/workflows/testflight.yml`（main への push で署名付きアーカイブ → App Store Connect へアップロード）

受け入れ条件
- [ ] core-tests と ios-build が緑
- [ ] testflight ワークフローは Secrets が揃えば動く構成になっている（Secrets 未登録時は PR に「開発者の作業待ち」と明記して `blocked` にする）
- [ ] 開発者が TestFlight からインストールして5タブが表示される

関連要件：なし（基盤）

### L1 データモデルと永続化

ゴール：すべての記録が SwiftData に保存され、iCloud 同期の土台ができる。

成果物
- `Packages/Core/Sources/Core/Models/` に純粋な値型（Codable）：`Session`, `Catch`, `Spot`, `Point`, `EnvSnapshot`, `Tackle`, `Rig`, `HookEvent`, `Species`
- `App/Sources/Services/Persistence/` に SwiftData の `@Model`（Core の値型と相互変換）
- CloudKit 連携の設定（コンテナ ID は `project.yml` の変数）
- 削除が分析に即時反映される設計（分析は保存データから毎回導出、キャッシュは無効化できる）

受け入れ条件
- [ ] Core のモデルに JSON の往復テスト
- [ ] アプリ起動時にストアが作られ、ダミー釣行を1件保存して再起動後も残る
- [ ] iCloud 同期は開発者の設定後に有効になる（未設定でもローカルで動く）

関連要件：F-22、§6

### L2 天文計算と潮汐エンジン（Core）

ゴール：通信なしで、全国どこでも何日先でも、潮位・満干・潮名・日の出入り・マズメ・月齢が出る。

成果物
- `Core/Astro/`：日の出・日の入・市民薄明（マズメ）、月齢・月相・月の出入り
- `Core/Tide/`：調和推算（分潮の振幅・遅角・天文引数・ノード因子）、満干検出、潮名（大潮〜長潮・若潮）、潮位変化率
- `scripts/fetch_jma_harmonics.py`：気象庁の分潮一覧表（60分潮）を全地点分取得して `data/tide/harmonics.json` に保存
- 最寄り地点の自動選択。分潮のない地点は気象庁潮位表テキストを年始に取得して補う仕組み（`Core/Tide/JMATideTableParser`）
- `data/tide/harmonics.json` を Core のリソースとして同梱

受け入れ条件
- [ ] 函館の推算値が気象庁潮位表（毎時潮位・満干）と数 cm・数分以内で一致するテスト
- [ ] 日の出入り・月齢が国立天文台の暦と1分・0.1以内で一致するテスト（函館・東京の数日分）
- [ ] 全国の地点リストから緯度経度で最寄りが引ける
- [ ] Linux の `swift test` のみで検証できる

関連要件：F-04、§2 時刻・潮汐・月

### L3 環境データ取得

ゴール：釣行中に §2 の全項目が自動でスナップショットされ、圏外でも止まらない。

成果物
- `App/Sources/Services/Environment/`：WeatherKit（現在＋取得できる最長範囲の予報）、CMAltimeter、Open-Meteo Marine（近傍の海上格子点を自動で選ぶ）、CoreMotion/HealthKit
- スナップショットのスケジューラ（30分ごと＋釣果時、環境 API は1時間間隔）
- 予報キャッシュと通信復帰後の実況差し替え
- Open-Meteo のクレジット文字列を設定画面用に用意

受け入れ条件
- [ ] 任意の緯度経度・時刻で `EnvSnapshot` が組み立てられる
- [ ] 機内モードでもキャッシュから組み立てられる（ユニットテストでネットワーク層をモック）
- [ ] 漁港内の座標で Open-Meteo が陸扱いになるケースを回避できる（オフセット探索）
- [ ] 1時間に1回を超えて外部 API を叩かない

関連要件：F-03、F-05、F-06

### L4 釣行セッション自動検出

ゴール：アプリを開かなくても釣行が始まり・終わり、釣り場が自動登録される。

成果物
- `App/Sources/Services/Session/`：ジオフェンス＋滞在検知（CLMonitor / Visits）、海岸線近傍判定、車速での終了、ランガンのまとめ
- 釣り場の自動作成と逆ジオコーディングによる名称候補
- 立ち位置の低頻度記録とポイント（メッシュ）化
- 誤検出時の破棄（通知アクション）
- しきい値を設定（感度3段階）で変えられる

受け入れ条件
- [ ] 位置のシミュレーション（GPX）で開始・終了・ランガンが期待通りになるテスト
- [ ] バックグラウンドで24時間動かしてクラッシュしない（開発者の実機確認）
- [ ] 通過だけでは開始しない

関連要件：F-01、F-02、§3

### L5 撮影と LiDAR サイズ推定

ゴール：魚を撮るだけで全長付きの釣果が保存される。

成果物
- `App/Sources/Features/Capture/`：ARKit/AVFoundation による深度付き撮影、計測枠の状態（遠い・近い・OK）、全長推定（魚の輪郭検出＋深度からの実寸換算）、推定幅
- 撮影時刻・位置・セッション・ポイント・タックル・リグの自動紐付け
- 連続撮影の同一個体マージ
- 標準カメラ写真の取り込み（PhotoKit、釣行中の時刻・位置に一致するもの）
- 深度のない写真はサイズ未計測として保存

受け入れ条件
- [ ] 既知サイズの物体（30cm 定規など）で ±2cm 以内（開発者の実機確認）
- [ ] 撮影から保存まで2秒以内
- [ ] 連続3枚が1尾にまとまる

関連要件：F-07、F-08、F-11、F-12、F-13、F-14

### L6 魚種判定

ゴール：北海道の根魚を中心に、オンデバイスで魚種が判定される。

成果物
- `App/Resources/Models/FishClassifier.mlmodel`（Core ML）。初期は公開データ＋開発者の写真で作る学習パイプライン `scripts/train_classifier/`（Create ML は Mac が必要なため、CI の macOS ランナーで学習する workflow を用意する）
- 対象魚種リスト `docs/species.md`
- 確信度と候補3種、修正による補正（端末内の補正テーブル）

受け入れ条件
- [ ] 主対象魚種のテストセットで Top-1 90% 以上（Top-3 98% 以上）
- [ ] 判定2秒以内
- [ ] 修正した結果が次回の候補順に反映される

関連要件：F-09、F-10、F-24

### L7 釣れ率エンジン（Core）

ゴール：現在地×時刻で 0〜100 のスコアと内訳、先の推移が出る。

成果物
- `Core/Score/`：ルールベースの基礎スコア（時間帯・潮・気圧傾向・風・波・水温・季節・月相）、自分データによる重み学習（釣行数に応じて混合）、魚種別スコア、内訳、確度（予報の有無）
- 先の推移の計算（データのある範囲まで、固定上限なし）
- イベント列の生成（次に変わる出来事：マズメ、満干、風の変化）

受け入れ条件
- [ ] ユニットテストで典型条件（朝マズメ×上げ潮×微風 → 高、昼×潮止まり×強風 → 低）が妥当
- [ ] ボウズの釣行を学習に使っても破綻しない
- [ ] 1日分の推移を 50ms 以内で計算

関連要件：F-16、F-17

### L8 統計・相関・レポート

ゴール：§5 の統計・相関・図鑑データ・釣行後レポートが自動で出る。

成果物
- `Core/Analytics/`：釣り場別・魚種別・時間帯別・月別・タックル別の集計、条件分布、前回比

- `App/Sources/Services/Report/`：Foundation Models による釣行後レポート生成（テンプレート文のフォールバック付き）
- 記録更新の判定（初魚種・自己記録・釣り場記録）

受け入れ条件
- [ ] Core の集計に固定データでのスナップショットテスト
- [ ] レポートが終了検出から10秒以内に生成される
- [ ] Foundation Models が使えない場合でもテンプレート文で成立

関連要件：F-18、F-19、F-20、F-21
